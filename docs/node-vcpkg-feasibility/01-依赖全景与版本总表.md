# 01 · 依赖全景与版本总表

## 1. Node 依赖结构拓扑

Node.js 的第三方依赖呈三层结构，层与层之间存在**重叠**（同一个库出现在两个层），这是本调研最需要厘清的地方：

```
┌────────────────────────────────────────────────────────────────────┐
│ 第 1 层：Node 直接依赖（deps/）                                     │
│   C/C++ 运行时库与本仓库内部工具                                      │
│   zlib openssl libuv(uv) cares brotli llhttp nghttp2 ngtcp2(含nghttp3) │
│   icu-small sqlite simdjson ada(ada-url) LIEF zstd histogram(剪裁)    │
│   libffi(v26) perfetto(v26) googletest inspector_protocol            │
│   nbytes ncrypto merve amaro postject uvwasi                          │
│   JS/npm 生态：npm undici acorn minimatch corepack(v24)              │
│   crates（Rust 依赖清单，仅 v26）                                    │
├────────────────────────────────────────────────────────────────────┤
│ 第 2 层：V8 引擎（deps/v8，node 维护的 fork）                         │
│   V8 14.6.202.34-node.37（v26） / 13.6.233.17-node.53（v24）          │
│   “-node.x” 后缀 = node 维护分支，V8 本身不可外接                     │
├────────────────────────────────────────────────────────────────────┤
│ 第 3 层：V8 third_party（deps/v8/third_party）                        │
│   构建期 C/C++：abseil-cpp simdutf zlib googletest highway rapidhash  │
│                 dragonbox(v26) fp16 fast_float                        │
│   工具/支持：jsoncpp ittapi inspector_protocol wasm-api siphash       │
│               utf8-decoder cpu_features re2(无源码)                    │
│   Python 构建链：jinja2 markupsafe colorama                           │
│   平台垫片：glibc valgrind vtune llvm-libc fuchsia-sdk zoslib         │
└────────────────────────────────────────────────────────────────────┘
```

### 1.1 重叠（同名库出现在多个层）——必须注意

| 库 | 第 1 层（node deps） | 第 3 层（v8 third_party） | 实际构建用哪个 |
|---|---|---|---|
| **zlib** | `deps/zlib` = Chromium zlib fork，`1.3.2.1-motley-<sha>` | v8 测试工具链自带的 zlib（v24: 1.3.0.1 / v26: 1.3.1） | **第 1 层**（node 运行时用 deps/zlib） |
| **googletest** | `deps/googletest`（Chromium fork 布局） | `v8/third_party/googletest`（另一份 Chromium fork） | 仅测试用，两层各管各的 |
| **inspector_protocol** | `deps/inspector_protocol` | `v8/third_party/inspector_protocol` | 生成 v8inspector 协议代码 |
| **icu** | `deps/icu-small`（裁剪 ICU 78.3） | v8 引用第 1 层 icu | 第 1 层 |

> 结论：v8 的 third_party 中与 node deps 重叠的 zlib/googletest 并不参与 node 运行时构建，vcpkg 化时只需处理第 1 层。但 v8 的 abseil-cpp/simdutf/highway 等是 v8 构建的真实依赖，它们**随 v8 树内嵌同步**，不能拆出去（vcpkg 无法与 v8 的 BUILD.gn 树解耦）。

## 3. 依赖关系与交叉引用速查

- **nghttp3 ↔ ngtcp2**：nghttp3 依赖 ngtcp2，node 只取二者的 `lib`（+ngtcp2 的 `crypto`）源码，需**同步升级**；vcpkg `nghttp3` port 另外依赖 `sfparse`（其 TLV 解析器，node 内置在 nghttp3 源码中）。
- **openssl → node:crypto / ncrypto / SEA / QUIC**：node 26 的 openssl 来自 openssl.org 官方 3.5.x（3.5 已合并 quictls 的 QUIC API；`docs/contributing/maintaining/maintaining-dependencies.md` 中 quictls 的表述已过时，`maintaining-openssl.md` 现已直接拉 `github.com/openssl/openssl`）。vcpkg `openssl` 3.6.3 新两个 minor。
- **zlib（deps/zlib）是 Chromium zlib fork**：`1.3.2.1-motley-<sha>` 中的 motley 是 chromium 对 madler zlib 补丁系列的代号（SIMD crc32/adler32、cpu_features 检测、inflate 改进）；与 vcpkg `zlib`（madler 官方）不同源。
- **LIEF**：node24 用 0.17.0（vcpkg 0.17.6 略新）；node26 直接用 1.0.0（vcpkg 0.17.6 落后一个 major）。LIEF 服务于 Single-Executable（node:sea）的二进制解析。
- **simdutf / simdjson / ada**：三个"现代 C++ 解析库"版本节奏都很快，node 均领先或同步 vcpkg，只有 simdutf 明显落后于 vcpkg。
- **uvwasi**：node 主创（nodejs/uvwasi），依赖 libuv，2023 年后基本停更，vcpkg 无 port，只能内嵌或自建 port。
- **crates/（仅 v26）**：Rust 依赖清单（用于 WASI 相关可选构建），走 cargo。
