# 架构重审：从「二进制配置」到「源码配置」

> 本文档是**一次独立于 CI 修复的架构级重审**，起因是用户提出的一组质疑：
>
> 1. 项目仍处早期，应审视**正确性**，而不是补丁式修复；
> 2. 倾向**完整理解后彻底重构**，真正符合 vcpkg 官方 port 的高要求；
> 3. 「从 node 二进制拿 `process.config`」这一步**能否彻底去掉**，改从源码取；
> 4. 「既然上游已有 CMake，直接用上游的会不会更好」；
> 5. 原则：**按最正确而不是改动最小的思想**重新过一遍，可实际改动代码做实验。
>
> 本文档记录：调研结论、决定性实验、发现的既有缺陷（含第一轮"修复"的真因被推翻）、  
> 以及据此形成的重构方案。

- 日期：2026-10-11
- 参与方法：全量阅读上游 node v24 源码 + 本机真实实验（Windows 本机）
- 关联文档：`docs/调研文档.md`（CI 运行史与逐轮修复记录）

---

## 0. 结论速览

| 质疑                               | 结论                                     | 依据    |
| -------------------------------- | -------------------------------------- | ----- |
| 能否从源码取配置，去掉二进制 `process.config`？ | **能，且已实验证明**                           | §3    |
| 上游已有 CMake，能否直接用？                | **不能——上游根本没有自研 CMake**                 | §1.1  |
| gyp 自带的 CMake generator 能用吗？     | **不能——官方明确否决**                         | §1.2  |
| 现有架构是否"补丁式"？                     | **是，且规模远超预期**                          | §2、§4 |
| 第一轮 macOS「缺 Security」修复是否正确？     | **错——真因是 collect.py 丢了顶层 `libraries`** | §4.2  |

**一句话**：应当保留「gyp → gyp2vcpkg → CMake」这条翻译路线（它经实验证明是唯一可行解），  
但必须做三处**结构性**修正，而不是继续打补丁：

1. **配置来源**：`env/<平台>.json`（二进制导出）→ 由 `configure.py` 从源码生成；
2. **依赖归属**：`node_shared_*` 全 `false` 导致 bundled 第三方源码被编译 →  
   用 `--shared-*` 让 gyp **自己**不加入，彻底废掉 `vendored/` 的手工剔除；
3. **字段完整性**：`collect.py` 只读 `configurations.<cfg>`、**丢弃目标顶层  
   `libraries`** → 补齐，还原 `-framework Security` / `Dbghelp` 等真实链接项。

## 1. 上游构建体系调研（否定两项假设）

### 1.1 「上游已有 CMake」——不成立

对 node v24 源码树全量核查：

- **`BUILD.gn` 头部原文**：
  > This file is used by GN for building, **which is NOT the build system used for  
  > building official binaries**. Please modify the gyp files if you are making  
  > changes to build system.
  → **GN 是非官方路径**（配套 `unofficial.gni`，文件名自带 "unofficial"）。
- **源码树内不存在自研 CMakeLists**。`deps/*/CMakeLists.txt`（如 ngtcp2、nghttp3、  
  uvwasi、simdutf 自带）是**依赖库自己的**，与 node 构建体系无关。
- **官方构建入口**是 `Makefile` + `configure.py` + gyp（`node.gyp` / `common.gypi` /  
  `node.gypi`）。**gyp 才是官方**。

**结论**：不存在"直接用上游 CMake"这条捷径。

### 1.2 gyp 自带的 CMake generator——官方否决

读取 `tools/gyp/pylib/gyp/generator/cmake.py`（1316 行）头部注释：

- "**under development** and should be considered **experimental**"
- "no support for building on platforms **other than Linux**"
- "**should not be relied on for building**"

**结论**：自研 gyp2vcpkg 翻译路线**必要且正确**，不是重复造轮子。

### 1.3 「从二进制取配置」的原设计

现有架构（`ports/node/project/config/seed_gypi.py` 自述）：

> 标准答案就在官方二进制里

即：把官方发布的 node 二进制跑出 `process.config` 导出成 JSON，作为 gyp 变量环境。  
问题在于——**官方二进制是"bundled 依赖"的产物**，其 `node_shared_*` **全部是 `false`**  
（见 §2.1），而 vcpkg 必须用系统依赖。**值本身就是错的**，后续所有"剔除 bundled"  
的动作都是在这个错误基线上打补丁。

## 2. 现有架构的"补丁式"痕迹（实测）

### 2.1 根因：`node_shared_*` 全 `false`

实测三平台 `env/*.json`（官方二进制导出）：

```
node_shared        = False
node_shared_ada    = False      node_shared_brotli     = False
node_shared_cares  = False      node_shared_gtest      = False
node_shared_hdr_histogram = False
node_shared_http_parser = False node_shared_libuv     = False
node_shared_merve  = False      node_shared_nbytes     = False
node_shared_nghttp2= False      node_shared_nghttp3    = False
node_shared_ngtcp2 = False      node_shared_openssl    = False
node_shared_simdjson = False    node_shared_simdutf    = False
node_shared_sqlite = False      node_shared_uvwasi     = False
node_shared_zlib   = False      node_shared_zstd       = False
```

**19 个全 `false`**。gyp 的语义（`node.gypi:178-250`）：

```python
[ 'node_shared_http_parser=="false"', { 'dependencies': ['deps/llhttp/llhttp.gyp:llhttp'] } ],
[ 'node_shared_uvwasi=="false"',     { 'dependencies': ['deps/uvwasi/uvwasi.gyp:uvwasi'] } ],
[ 'node_shared_ada=="false"',        { 'dependencies': ['deps/ada/ada.gyp:ada'] } ],
...
[ 'node_shared_zstd=="false"', { 'dependencies': ['deps/zstd/zstd.gyp:zstd'],
                                 'defines':    ['NODE_BUNDLED_ZSTD'] } ],
```

→ `false` 时 gyp **主动把 bundled 源码加进依赖树**。这正是"应在源码取配置"的  
致命之处：官方二进制就是这么编的。

### 2.2 现有产物的 bundled 残留（实测）

`ports/node/project/generated/*.cmake` 中 `deps/` 引用全集（**20 个**）：

```
deps/ada          deps/brotli      deps/cares        deps/googletest
deps/histogram    deps/inspector_protocol            deps/llhttp
deps/merve        deps/nbytes      deps/ncrypto      deps/nghttp2
deps/openssl      deps/postject    deps/simdjson     deps/sqlite
deps/uv           deps/uvwasi      deps/v8           deps/zlib
deps/zstd
```

其中**确实有源码被编译**的（实测源文件数）：

| 目录            | 被编译的源文件数 |
| ------------- | -------- |
| `deps/uvwasi` | 9        |
| `deps/merve`  | 1        |
| `deps/nbytes` | 1        |

### 2.3 补丁痕迹清单

| 位置                                                   | 手法                                                          | 性质                       |
| ---------------------------------------------------- | ----------------------------------------------------------- | ------------------------ |
| `project/vendored/CMakeLists.txt`                    | 手工列 6 个目标（nbytes/merve/crdtp/uvwasi/ncrypto/ncrypto_engine） | 手工抵消 gyp 的 bundled 行为    |
| `consume.cmake:279` `node_port_drop_bundled_include` | 事后从 include 路径里"摘"                                          | 只摘 include，**源码仍被编**     |
| `config.json` 的 `define_overrides`                   | 只有 2 项（`icu_gyp_path`、`v8_embedder_string`）                 | **并未覆盖 `node_shared_*`** |
| 规模                                                   | 48 个目标手工建、**1148 行**手写 CMake                                | 维护负担                     |

## 3. 决定性实验：从源码生成配置，bundled 全部消失

### 3.1 实验设计

在**纯源码**（未编译）目录上跑上游 `configure.py`，用 `--shared-*` 显式开启系统依赖，  
生成 `config.gypi`，替代 `env/*.json` 喂给 gyp2vcpkg，观察产物变化。

### 3.2 实验步骤与结果

**步骤 1 — 生成配置（Windows 交叉配置）**

```bash
python configure.py --dest-os=win --dest-cpu=x64 \
  --shared-libuv --shared-openssl --shared-zlib --shared-brotli --shared-cares \
  --shared-nghttp2 --shared-ngtcp2 --shared-sqlite --shared-simdjson --shared-hdr-histogram \
  --shared-zstd --shared-ada --shared-simdutf --shared-nghttp3 --shared-http-parser \
  --shared-merve --shared-nbytes --shared-uvwasi
# → INFO: configure completed successfully
```

**全部 18 个 `--shared-*` 被接受**（含我先前误判为"不支持"的 zstd/ada/simdjson/simdutf/  
nghttp3/http-parser —— 它们在 `configure.py:327-587` 均有定义）。

**步骤 2 — 核对生成的 `config.gypi`**

```
node_shared_ada      = 'true'     node_shared_brotli   = 'true'
node_shared_cares    = 'true'     node_shared_http_parser = 'true'
node_shared_libuv    = 'true'     node_shared_merve    = 'true'
node_shared_nbytes   = 'true'     node_shared_nghttp2  = 'true'
node_shared_nghttp3  = 'true'     node_shared_ngtcp2   = 'true'
node_shared_openssl  = 'true'     node_shared_simdjson = 'true'
node_shared_simdutf  = 'true'     node_shared_sqlite   = 'true'
node_shared_uvwasi   = 'true'     node_shared_zlib     = 'true'
node_shared_zstd     = 'true'     node_shared_hdr_histogram = 'true'
node_shared_gtest    = 'false'   (gtest 非运行时依赖，保持 bundled 合理)
```

**19 个中 18 个转 `true`**，变量总数 109（与官方二进制导出的 108 同量级）。

**步骤 3 — 喂给 gyp2vcpkg 跑完整三步**

```
resolve win   → gyp_resolved.json (110 targets)
collect win   → compile_config_win.json（42 目标 / 13 动作）
generate      → exp-out（54 份片段）
```

**步骤 4 — 对比 bundled 残留**

| 目录            | 现有产物   | 实验产物  |
| ------------- | ------ | ----- |
| `deps/uvwasi` | 9 个源文件 | **0** |
| `deps/merve`  | 1 个源文件 | **0** |
| `deps/nbytes` | 1 个源文件 | **0** |

**`deps/` 引用全集对比**：

|    | 现有产物                                                                                                                                                                                       | 实验产物                                                              |
| -- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| 数量 | **20**                                                                                                                                                                                     | **5**                                                             |
| 明细 | ada / brotli / cares / googletest / histogram / inspector_protocol / llhttp / merve / nbytes / ncrypto / nghttp2 / openssl / postject / simdjson / sqlite / uv / uvwasi / v8 / zlib / zstd | cares / googletest / inspector_protocol / ncrypto / postject / uv |

**消失的 15 个全部是第三方 bundled 依赖**（ada/brotli/histogram/llhttp/merve/nbytes/  
nghttp2/openssl/simdjson/simdutf/sqlite/uvwasi/zlib/zstd/hdr_histogram）。

**保留的 5 个逐一核实为"必需"**：

| 保留项                            | 性质                             | 判定    |
| ------------------------------ | ------------------------------ | ----- |
| `cares/include`、`uv/include`   | 仅 include 目录（系统库头文件转发）         | 必需，保留 |
| `inspector_protocol` / `crdtp` | **node 自己的源码**（vcpkg 无对应 port） | 必需，保留 |
| `ncrypto`                      | node 自己的加密封装                   | 必需，保留 |
| `postject`                     | node 自带的打包工具                   | 必需，保留 |
| `googletest/include`           | 仅 include 路径，node_base 不编译其代码  | 无害    |

**目标数变化**：`merve` / `nbytes` / `ncrypto_engine` / `uvwasi` **4 个目标从依赖树中消失**  
（gyp 自己不加了），`config.json` 的 `targets` 列表 46 → 42。

### 3.3 三平台交叉验证（Windows 本机一次生成三平台配置）

进一步验证：**在 Windows 本机**分别以 `--dest-os=linux` / `--dest-os=mac` 生成配置。

| 平台    | `configure.py` 结果                               | `config.gypi`            | shared=true 数 | `gyp2vcpkg resolve` |
| ----- | ----------------------------------------------- | ------------------------ | ------------- | ------------------- |
| win   | 成功                                              | 20946 B / 109 变量         | 18            | 110 targets ✅       |
| linux | 成功                                              | 生成                       | 18            | **110 targets ✅**   |
| mac   | **gyp 那步报 `No Xcode or CLT version detected!`** | **仍生成** 21235 B / 106 变量 | 18            | **110 targets ✅**   |

**mac 的关键发现**：`configure.py --dest-os=mac` 在非 macOS 上会因 `xcodebuild` 探测  
失败而**在 gyp 步骤报错**，但 `config.gypi` **已经先写出来了**（`configure.py:2613`  
在调 gyp **之前**就 `write('config.gypi', ...)`）。且缺失的 `xcode_version` 变量：

- 在 `common.gypi` / `node.gyp` / `node.gypi` / `tools/v8_gypfiles/*.gyp` 里  
  **完全没有被引用**（全量 grep 零命中），它只是 `process.config` 的透传信息项；
- 缺失它**不影响 gyp 求值** —— 实测用这份 mac 配置跑 `resolve`，  
  **110 targets 全部解析成功**。

**结论**：三平台配置**都能在 Windows 本机一次生成**，CI 的 macOS/linux job  
不再需要"跑官方二进制取配置"这一步。若要消除 mac 的报错噪音，可在  
`configure.py` 后忽略其退出码 / 仅取 `config.gypi`（因该文件先于失败步骤写出）。

### 3.4 实验结论

> **`--shared-*` 是从源头消除 bundled 依赖的正确手段。**  
> 一旦 `node_shared_* = 'true'`，gyp **自己**就不把 bundled 源码加进目标——  
> `vendored/CMakeLists.txt` 的手工剔除、`node_port_drop_bundled_include`  
> 的后事摘取，**全部可以删除**。

同时证明：**「从二进制取 `process.config`」这一步可以彻底去掉**，  
且比从源码取是**错误**的——因为官方二进制的 `node_shared_* = false` 是"为 bundling 而设"的。

## 4. 相对性缺陷：`collect.py` 丢弃目标顶层 `libraries`

### 4.1 缺陷定位

`collect.py:107-120` 的 `_extract_config(td, gyp_dir, config_name)` 只从  
**`td["configurations"][config_name]`** 里取字段：

```python
def _extract_config(td, gyp_dir, config_name):
    cfg = (td.get("configurations") or {}).get(config_name, {})
    out = {}
    for f in _CONFIG_FIELDS:
        v = cfg.get(f)
        ...
```

而 gyp 的 `libraries` 挂在**目标顶层**（`_dump_generator.py` 输出的  
`target_dicts[<qualified>]["libraries"]`），**不在 `configurations.<cfg>` 下**。

`generate.py` 的 `_list_of(d, "libraries")` 读的是  
`d["config"]["libraries"]`，因此**永远读不到**。

### 4.2 后果：第一轮「macOS 缺 Security」的真因被推翻

实测 mac 平台 gyp 解析结果：

```json
node_base:
  configurations.Release.xcode_settings.OTHER_LDFLAGS = ["-framework CoreFoundation"]
  libraries (顶层)                                     = ["-framework CoreFoundation -framework Security"]
```

**上游 gyp 是有 `Security` 的**（`node.gypi:252-258`）：

```python
[ 'OS=="mac"', {
  # linking Corefoundation is needed since certain macOS debugging tools
  # like Instruments require it for some features. Security is needed for
  # --use-system-ca.
  'libraries': [ '-framework CoreFoundation -framework Security' ],
}],
```

→ 第一轮结论「上游已迁 CMake/GN，gyp 里没有 Security」**是错误的**。  
真因是 **`collect.py` 丢了顶层 `libraries`**，而 `consume.cmake` 里硬编码的  
`target_link_options(... "-framework Security")` 只是**掩盖**了这个缺陷。

### 4.3 影响面（三平台实测）

| 平台        | 有顶层 `libraries` 的目标 | 被丢弃的关键链接项                                                                                                                                            |
| --------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **win**   | **12**              | `node_base`: `Dbghelp`/`Psapi`/`Winmm`/`Ws2_32`；`node`: `ole32`/`iphlpapi`/`psapi`/`shell32`/`userenv`/`uuid` 等                                      |
| **linux** | **15**              | `node`: `-ldl -lm`；工具链(`mksnapshot`/`torque`/`bytecode_builtins_list_generator`/`gen-regexp-special-case`): `-ldl -lrt`；`node_js2c`: `-lm -ldl -lrt` |
| **mac**   | **13**              | `node`/`node_base`/`libnode`/`cctest`/`embedtest`/`node_mksnapshot`/fuzz 系列: `-framework CoreFoundation -framework Security`                         |


**这意味着**：Windows 上 `node_base` 根本没链 `Dbghelp/Winmm/Ws2_32`，  
目前能编译通过靠的是其他目标顺带把库带进来（或 `#pragma comment(lib)` 兜底）——  
**"能跑但不对"**。跨平台一旦调整链接顺序就会暴露。

附加缺陷：`'-framework CoreFoundation -framework Security'` 是**一个字符串含两项**，  
`generate.py:344` 对 `xcode_settings.OTHER_LDFLAGS` 做了 `_f.split()` 拆分，  
但**对 `libraries` 字段没有**。补齐 `libraries` 时必须同时加拆分。

## 5. 重构方案

### 5.1 三处结构性修正

| #     | 位置    | 现状                                                               | 改为                                                                      |   |       |      |                                                                     |                                                                                     |
| ----- | ----- | ---------------------------------------------------------------- | ----------------------------------------------------------------------- | - | ----- | ---- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| **A** | 配置来源  | `config/seed_gypi.py` 从 `env/<平台>.json`（二进制导出）读 `process.config` | 调上游 `configure.py` 在源码上生成 `config.gypi`，并按 vcpkg 依赖**显式传 `--shared-*`** |   | **B** | 依赖归属 | `node_shared_* = false`，靠 `vendored/` + `drop_bundled_include` 事后剔除 | `node_shared_* = true`，gyp 自己不加；**删除** `project/vendored/` 与 `drop_bundled_include` |
| **C** | 字段完整性 | `collect.py` 只取 `configurations.<cfg>`                           | 合并**目标顶层** `libraries` / `ldflags` 等，并对含空格项做拆分                          |   |       |      |                                                                     |                                                                                     |

### 5.2 A 的具体实现要点

- `configure.py` 的调用**不改上游一行**（符合"从源码取"的精神）：
  ```
  python configure.py --dest-os=<win|linux|mac> --dest-cpu=<arch> \
      --shared-libuv --shared-openssl --shared-zlib --shared-brotli --shared-cares \
      --shared-nghttp2 --shared-ngtcp2 --shared-sqlite --shared-simdjson \
      --shared-hdr-histogram --shared-zstd --shared-ada --shared-simdutf \
      --shared-nghttp3 --shared-http-parser --shared-merve --shared-nbytes --shared-uvwasi
  ```
- `--dest-os` 支持交叉指定（实验已证明 Windows 上可生成 linux/mac 配置），  
  因此**三平台配置可在同一台机器上一次生成**，CI 不再需要"跑官方二进制取配置"这一步。
- 已核实三平台变量交集充分：win/linux/mac 与各自 `env/*.json` 相比，  
  **107/108 个变量同名同义**，差异仅在环境探测项（`nasm_version`、`gas_version`、  
  `xcode_version`、`openssl_no_asm`），**不影响 gyp 求值**。
- 注意：`--shared-*` 与 `--openssl-no-asm` **互斥**（报  
  `ERROR: --openssl-no-asm is incompatible with --shared-openssl`），vcpkg 侧二选一。

### 5.3 B 的具体实现要点

- `config.json` 的 `targets` 从 46 项裁到 42 项（去掉 merve/nbytes/ncrypto_engine/uvwasi）；  
  建议改为**自动取依赖闭包**，避免手工名单随上游漂移。
- `project/vendored/CMakeLists.txt` 整个删除（6 个手工目标不再需要）。
- `consume.cmake` 删除 `node_port_drop_bundled_include`。
- **但要注意**：gyp 里 `node_shared_*=="true"` 只是"不加 bundled 源码"，  
  **不会自动 `target_link_libraries` 到系统库**——系统库的链接仍需调用方  
  （vcpkg 的 portfile / consume 层）自己写。这部分**不是补丁，而是职责分工**：  
  gyp 管"编什么"，vcpkg 管"链什么"。

### 5.4 C 的具体实现要点

- `_extract_config` 增加"顶层字段"合并：`libraries` / `ldflags` / `defines` 等  
  在 gyp 里既可能出现在 `configurations.<cfg>`，也可能出现在目标顶层。
- 合并后对 `libraries` 也做 `split()` 拆分（与 `OTHER_LDFLAGS` 一致）。
- 补完后应能**回退第一轮 macOS 的硬编码补丁**  
  （`consume.cmake` 里 `if(APPLE AND name STREQUAL "node_base")` 那段），  
  因为 `-framework Security` 会从 gyp 正确带出来。

### 5.5 不做的事（明确否决）

| 方案                                        | 否决理由                                              |
| ----------------------------------------- | ------------------------------------------------- |
| 直接用上游 CMake                               | 上游无自研 CMake（§1.1）                                 |
| 用 gyp 自带 cmake generator                  | 官方明确否决（§1.2）                                      |
| 保留二进制取配置                                  | 值本身错误（§2.1）                                       |
| 继续用 `vendored/` 手工剔除                      | 补丁性质，随上游漂移必坏                                      |
| 改走 `vcpkg_configure_make` + 上游 `Makefile` | 需保留完整 Makefile 工具链，且失去 CMake 集成的可组合性；**留作备选**，非首选 |
