# Skips for Node.js's own test suite - the single source of truth, read by
# test/official_suite/CMakeLists.txt.
#
# Format, one per line:  <test name> | <platform> | <reason>
#
#   <test name>   the driver's name for it: no .js suffix, no test/<suite>/ prefix
#                 (test/parallel/test-fs-rm.js is written as test-fs-rm).
#   <platform>    all / windows / linux / macos, optionally narrowed with -<arch>
#                 (windows-x64, macos-arm64). Unrecognized values simply never match, so a
#                 typo makes the case run instead of hiding it.
#   <reason>      mandatory. An entry without one fails the configure step.
#
# Before adding anything here:
#
#   * Upstream already marks cases SKIP or FLAKY in each *.status file and the driver honours
#     those. Listing them again is a duplicate and it freezes upstream's decision.
#   * A test that fails because a file is missing is usually our installation being
#     incomplete - install the file, do not skip the test.
#   * Anything that crashes in native code is our build until proven otherwise. Cross-check
#     against the official Node.js binary first: official passes and ours fails means look
#     here, not at Node.js.
#
# Every entry is re-examined whenever the pinned Node.js version changes.

# -- Pending an official-binary cross-check ------------------------------------
#
# The five entries below are the residual failures of the first run that put
# Node.js's own suite on every push (2026-10-18: 5003 passed, 5 failed). Four of
# them are Windows ACL cases and one is a shell-name case; each is written down
# with what was measured rather than with a theory.
#
# They are not proven to be the runner's rather than this repository's. The
# discipline this file asks for is a cross-check against the official Node.js
# binary on the same runner - official passes and ours fails is the only thing
# that makes one of these ours - and that cross-check is not wired into CI yet.
# Until it is, treat these five as the known-open set. The cross-check itself is
# tracked as an issue (#21), because it is a work item with a closing condition
# rather than a fact.

# The case asserts that the warning hint contains the literal text
# "Use `node --trace-warnings". Node.js builds that hint from the executable's
# own name, and the shell here is node_embed, so the hint says node_embed and the
# assertion's match comes back null. This one is ours by design rather than a
# defect: the alternative is naming the embedding executable `node`, which is
# what upstream's suite assumes throughout.
test-snapshot-warning | all | asserts the hint literally names node; this shell is node_embed

# All four below drive icacls to deny themselves access and then assert EPERM,
# or hand icacls a path it has to survive. They pass on an ordinary Windows
# machine with this port's executable and fail on a GitHub-hosted Windows
# runner, which runs the job as an account in the Administrators group - a deny
# ACE is not the same obstacle for an elevated process.
test-fs-rm | windows | icacls /deny does not stop an elevated process, so the expected EPERM never comes
test-fs-mkdir-recursive-eaccess | windows | same icacls mechanism; measured passing locally as an ordinary user
test-fs-rmSync-special-char-additional-error | windows | icacls is handed a non-ASCII path and reports it as not found

# Exercises whatever shells the machine has - cmd, PowerShell, and any bash on
# PATH - by symlinking each into a directory whose name contains spaces. On a
# GitHub-hosted runner one of them returns exit status 1 for "echo foo bar".
# Already in the symlink skip list, because on a machine without that privilege
# it never gets as far as the shells.
test-child-process-exec-any-shells-windows | windows | depends on the shells installed; "echo foo bar" exits 1 on the runner

# -- Windows ------------------------------------------------------------------
# The TypeScript compiler emits CRLF on Windows while the fixture expects LF. Upstream test
# bug, reproduced here with the port-built executable; the mechanism is the "line endings in
# generated output" category in docs/node-suite.md, section 4.
test-snapshot-typescript | windows | tsc emits CRLF on Windows, the fixture compares against LF

# The test asserts empty stderr and the environment carries both NO_COLOR and FORCE_COLOR,
# which makes Node.js print a warning about that combination. Measured 2026-10-16 with a
# port-built executable; re-check against the official binary before trusting this entry,
# because an environment difference could just as easily be ours.
test-runner-reporters | windows | NO_COLOR and FORCE_COLOR both present in the run environment
